## Browser audio-format correction

The user's loud/fast/distorted playback exposed a real callback-format defect
that the earlier nonzero host PCM and UI-only browser checks did not catch.
`SDL_OpenAudio(desired, obtained)` permits format changes. The pinned browser
backend negotiates F32, but our callback writes S16 and divides byte length by
two. Interpreting those signed-16 bits as floats corrupts the waveform and
advances the mixer twice as far per output buffer. This is not an artist-track
tempo change. See [SDL's documented negotiation contract](https://wiki.libsdl.org/SDL2/SDL_OpenAudio).

Web now opens a device allowing only frequency and buffer-size changes, keeping
the callback S16/stereo while SDL converts to Web Audio F32. Mixer timing uses
the obtained frequency. Web-only master gain is 0.25 (approximately -12 dB),
including existing 100% preferences; native device behavior is unchanged.

Speaker-free contract regression tests verify one-second source progression
at both 44.1 and 48 kHz and <=7500 signed-16 peak for a 30000-peak test signal.
All 36 host-decoded tracks, empty packaging and the 47 BYOD browser checks
pass again. A new test-only bootstrap measures actual browser output PCM,
then clears every output buffer and additionally routes through zero gain.
After a trusted test click unlocks the suspended 48 kHz AudioContext, actual
F32 samples are nonzero, finite and below full scale (6,029,312 samples over
736 callbacks, observed peak 0.070435, zero invalid samples). This is sample-level verification, not a claim
of subjective listening on the user's browser or headphones. Test interception
is never copied into the shipped app.
